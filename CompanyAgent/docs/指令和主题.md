# 斜杠指令、界面重做和主题

版本 1.1 · 2026-11-21 · 给实现的人看的规格。

用户看了聊天为主的界面之后的两条意见，原话：

1. "现在不能使用 `/` 后面各种指令"
2. "现在的前端 UI 界面也很丑，你多找几个设计去看看，多给几个主题，自己选"

所以这一轮做三件事：斜杠指令、整体视觉重做、主题（多套，用户自己选）。

界面原则不变：使用者是世界 500 强公司的管理者；简洁，有程序员工具的利落感，一看就会用；文字直白、短。

## 0. 现在的界面哪里不好看

我把现在的界面渲染出来看过了（截图在云端工作区 `/home/claude/shots/v6_*.png`）。问题不在布局，布局是对的；问题在"没有主意"：

- 灰蓝色侧栏、纯白主区、一个高饱和的宝蓝色按钮，是任何后台系统的默认长相。
- 到处是 1 像素描边：新对话按钮、搜索框、"+"、麦克风、批准方式、建议按钮，全都描了边，画面碎。
- 字小、行距紧，侧栏底部的导航是一列裸文字，没有图标，没有层次。
- 输入框比对话正文宽，中轴没对齐；框里还塞了一句"回车发送，Shift + 回车换行"。
- 对话里出现了给开发者看的话："没有安装 LangChain / LangGraph，当前使用过渡内核。安装方法：pip install -r requirements.txt"。管理者不该看到这个。
- 标题字重太重，页面像表单，不像一个每天要用的工具。

## 1. 斜杠指令

### 1.1 怎么触发

- 在输入框里，第一个字符打 `/`，输入框上方弹出指令菜单（新对话页和对话页都一样）。继续打字就筛选：按中文名、英文别名、说明里的字都能匹配。
- 上下键选，回车或 Tab 确认，Esc 关掉（关掉后 `/` 留在输入框里，当普通文字）。鼠标点也行。
- 不带参数的指令，确认后立即执行并清空输入框。带参数的指令，确认后把 `/指令名 ` 填进输入框，等用户写参数，回车执行。
- 打了 `/xxx` 却不是任何指令（比如一个路径 `/Users/…`），按回车就当普通消息发出去，菜单里显示一行"没有这个指令，回车会当普通消息发送"。
- 入口要让人发现：占位符末尾加"输入 / 看指令"；"+"菜单里加一项"指令…"。

### 1.2 有哪些指令

每个指令有一个中文名和一个英文别名，两个都能用（`/新对话` 和 `/new`）。菜单分三组：指令、技能、模板。

| 指令 | 别名 | 作用 |
|---|---|---|
| `/新对话` | `/new` | 开一个新对话 |
| `/停止` | `/stop` | 停下正在做的事（只在运行中出现） |
| `/继续` | `/continue` | 接着做（只在停下时出现） |
| `/整理 [要保留的重点]` | `/compact` | 把较早的过程压成摘要，腾出上下文。可以写要保留什么 |
| `/改名 <新标题>` | `/rename` | 改这个对话的标题 |
| `/导出` | `/export` | 导出对话记录 |
| `/删除` | `/delete` | 删除这个对话（先确认） |
| `/搜索 <词>` | `/search` | 搜以前的对话 |
| `/记住 <内容>` | `/remember` | 直接记进"关于我"，不经过模型。成功后给一条提示，带撤销 |
| `/记忆` | `/memory` | 打开记忆页 |
| `/技能` | `/skills` | 打开技能页 |
| `/存成技能` | `/save-skill` | 在当前对话里发一句"把这次的做法存成技能" |
| `/文件` | `/file` | 添加文件 |
| `/文件夹` | `/folder` | 用一个文件夹工作 |
| `/批准 [每步都问\|自动\|全放行]` | `/mode` | 改批准方式；不带参数就弹出选择 |
| `/主题 [主题名]` | `/theme` | 换主题；不带参数就打开主题选择 |
| `/状态` | `/status` | 显示一张小卡片：用的哪个模型和内核、这个对话用了多少上下文、记忆用量 |
| `/定时` `/资料` `/设置` | `/schedule` `/kb` `/settings` | 打开对应页面 |
| `/帮助` | `/help` | 列出全部指令 |

**技能。** 每个技能是一条指令：`/slides 把季度数据做成 5 页`。菜单里显示技能的描述。发送时带上 `skill` 字段（见 1.3），用户气泡上显示一个"技能：slides"的小标签。

**模板。** 每个任务模板是一条指令，用模板的标题当名字。确认后把模板文字填进输入框，不直接发送。

只对当前状态有意义的指令才出现（没有打开对话时，不出现停止、继续、整理、改名、导出、删除、存成技能）。

### 1.3 后端要配合的

- **点名用技能。** 发消息的两个接口（`POST /api/sessions`、`POST /api/sessions/<id>/message`）增加可选的 `skill`（技能名，必须存在，否则 400）。存进 `user_message` 事件的 payload。给模型看的时候，在这条发言后面加一行：`（用户点名要用技能「slides」：先用 skill_load 读它的说明，再照着做。）`。两个内核都做，做法和附件一样。
- **手动整理。** `POST /api/sessions/<id>/control`，`{"op": "compact", "focus": "可选，要保留的重点"}`。只在对话没有在运行时接受（运行中回 409）。过渡内核：直接调现有的压缩，`focus` 加进压缩提示里；没有可压的内容时返回 `{"ok": true, "compacted": false}`。新内核：账本里写下摘要之后，要让这个对话的 LangGraph 检查点失效，下次运行从账本重新装载；用现有的装载和遗忘机制做，确实做不到就对新内核回 `{"ok": false, "error": "…"}`，并在 `docs/内核迁移说明.md` 里写明。
- **改标题。** `PATCH /api/sessions/<id>`，`{"title": "…"}`，1 到 60 个字符。
- **主题存进设置。** 设置里增加 `ui.theme`（主题 id，匹配 `^[a-z0-9-]{1,32}$`，默认 `auto`）。`GET /api/settings` 带上，`POST /api/settings` 接受。这样换个浏览器打开还是同一个主题。
- **静态文件。** 增加 `/theme.js` 和 `/themes.css`（界面同事提供这两个文件：前者在页面最前面加载，先把主题设好，避免闪一下默认主题；后者是全部主题的颜色变量）。文件不存在时回 404，不要报错。
- **对话里不再出现内核提示。** 运行时往每个对话发的那条"没有安装 LangChain / LangGraph…"的 `notice` 去掉。`GET /api/state` 里保留 `kernel`，增加 `kernel_notice`（没有就是 `null`），界面放到设置页和 `/状态` 里显示。
- **状态。** `GET /api/sessions/<id>/status`，给 `/状态` 用：`{"model": "…", "kernel": "langgraph|builtin", "context": {"used": 估算的 token 数, "limit": 上限}, "steps": 已做的工具步数, "memory": {"user": {"used": n, "limit": n}, "workspace": {…}}, "approval_mode": "…"}`。`context.used` 用现有的上下文估算办法，算的是"下一次请求大概会发多少"。
- 以上每一项都要有测试。新内核的对应测试写进 `tests/test_lg_*.py`，没装包时跳过。

## 2. 视觉重做

### 2.1 方向

这是一个管理者每天打开的工作工具。它要像一张干净的办公桌：东西少，摆得整齐，要用的就在手边。程序员工具的"利落"体现在对齐、等宽数字、键盘可达、状态一眼可辨，不体现在把界面做成终端。

五条原则：

1. **少线条。** 用底色的深浅分区，不靠描边。按钮默认没有边框，只有主要动作有底色。保留的线只有：侧栏和主区之间、页面里大段之间。
2. **字大一点，行距松一点。** 正文 15px、行高 1.7（中文要比英文松）；侧栏 14px；标题 600 字重，不用更重的。
3. **一个强调色。** 只用在两处：主要动作（发送、批准、保存）和需要用户处理的地方（等批准、等回答）。成功、警告、出错用低饱和的状态色，和强调色分开。
4. **输入框是主角。** 大圆角，柔和的阴影，里面的按钮是图标；和对话正文同宽、同一条中轴。那句"回车发送…"的提示去掉，放进发送按钮的 `title`。
5. **动得少。** 菜单 120 毫秒淡入；流式输出时一个光标；批准卡片出现时轻轻一下。别的不动。尊重 `prefers-reduced-motion`。

### 2.2 字体

不带字体文件（内网、没有构建步骤），用系统字体，但要挑：

```css
--font-sans: -apple-system, "SF Pro Text", "PingFang SC", "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
--font-mono: "SF Mono", "Cascadia Code", "JetBrains Mono", Consolas, "Noto Sans Mono CJK SC", monospace;
--font-serif: "Songti SC", "STSong", "SimSun", "Noto Serif CJK SC", serif;   /* 只有"公文"主题的标题用 */
```

数字用等宽数字（`font-variant-numeric: tabular-nums`）：用量、步数、时间、文件大小。字号阶梯：12 / 13 / 14 / 15 / 17 / 20 / 26。

### 2.3 版面

- **侧栏**（宽 260，可以收起成只有图标的一条）：每一项前面有一个线条图标（自己用内联 SVG 画，线宽 1.5，16×16，风格统一）。"新对话"是侧栏里最显眼的一行，但不描边。对话列表的当前项用底色标出。底部导航带图标。
- **新对话页**：问候和输入框在页面上部三分之一处，居中。问候按时间变（"上午好""下午好""晚上好"），下面一行小字"想做什么？"。建议在输入框下面一行。
- **对话页**：正文列宽 720 到 760，居中。用户气泡靠右，用强调色的浅底。助手正文靠左，不带框。步骤行是一条细的轨：左边一个状态点，文字"做了 5 步"，右边耗时；展开后每一步一行，图标加一句话。顶部栏很薄：标题用正常字重，状态标签只在运行中、等你处理、出错时显示。每条助手回答下面有一个"复制"小按钮（悬停或聚焦时出现）。
- **批准卡片**：要让人一眼看懂"它想做什么、会改什么"。标题一句话，下面是关键参数（路径、文件名），内容预览放在可滚动的块里；两个按钮"同意""不同意"，主按钮用强调色。
- **各个页面**（记忆、技能、定时、资料、设置）：统一的页头（标题加一句说明），内容分组用留白和小标题，少用框。设置页第一组是"外观"（主题选择）；模型地址、内核这些技术项放到页面最后的"高级"里，默认收起。
- **窄窗口**：760 以下侧栏变成抽屉；输入框贴底；页面单栏。

### 2.4 Markdown 里的东西

表格（表头底色、行间细线、数字右对齐）、代码块（等宽、底色、右上角"复制"）、行内代码、引用、列表、链接、分隔线，都要在每个主题下好看。助手回答里的长表格可以横向滚动，不撑破版面。

## 3. 主题

### 3.1 机制

- 所有颜色走 CSS 变量，挂在 `:root[data-theme="…"]` 上，全部放在 `ui/themes.css` 一个文件里（`app.css` 里只用变量，不定义颜色）。`data-theme="auto"`（默认）时，浅色系统用"素白"，深色系统用"墨夜"；脚本没有运行（没有 `data-theme`）时也一样，用 `@media (prefers-color-scheme: dark)` 兜底。
- 语义变量（每个主题都要定义全）：`--bg`（主区）、`--bg-side`（侧栏）、`--surface`（卡片、输入框）、`--surface-2`（悬停、次级底色）、`--border`、`--border-strong`、`--text`、`--text-2`、`--text-3`、`--accent`、`--on-accent`（强调色上的字）、`--accent-soft`（强调色的浅底，用户气泡）、`--link`、`--ok`、`--warn`、`--err`、`--code-bg`、`--focus`、`--shadow`、`--selection`。组件里不许出现写死的颜色。
- **选主题**：设置页"外观"里是一排主题卡片，每张卡片是一个小预览（用那个主题自己的变量画出侧栏条、一个气泡、一个强调色按钮），下面是名字和"浅色 / 深色"。点一下立刻换，不用保存。`/主题` 指令和"查找和跳转"里也能换。
- **记住**：先写进 `localStorage`（立即生效），再存到后端设置 `ui.theme`。页面最前面加载的 `theme.js`（十来行）从 `localStorage` 读出来设好 `data-theme`，避免先闪一下默认主题。启动后拿到后端设置，如果和本地不同，以后端为准。`localStorage` 用不了时不报错。
- **对比度**：正文和 `--text-2` 对各自的底色不低于 4.5:1；`--text-3`、占位符不低于 3:1；强调色按钮上的字不低于 4.5:1；焦点环看得见。写一个 Node 脚本算每个主题的这几组对比度，放进 `tests/ui_test.mjs`，不达标就失败。社区配色里原本对比度不够的地方，可以在同一套色板里换一个更深或更浅的颜色，不要自己发明颜色。

## 6. 实现情况（2026-11-21）

全部做完，已经写进项目。和上面的规格有出入的地方：

- **批准卡片的按钮还是"批准 / 拒绝"**，没有改成 2.3 节写的"同意 / 不同意"。整个产品用的都是"批准"这个词（批准方式、等你批准、已批准），一个动作从头到尾一个名字。
- **`/整理` 在后台做。** 接口立刻返回 `{"ok": true, "started": true}`，结果通过事件告诉界面（`compact` 事件：started / done / failed）。没有可整理的内容时返回 `{"ok": true, "compacted": false}`。
- **多了拼音。** 21 条内置指令都能用拼音全拼或首字母找到（`/ji`、`/xdh`）。
- **`/状态` 不显示给开发者看的话。** 内核一行写"LangGraph"或"过渡内核"，安装提示只在 设置 → 高级 里。
- **状态接口多一个字段** `compacting`（是否正在整理）。`context.limit` 是输入预算（自动整理的触发线），不是整个上下文窗口。
- **Solarized Light 和 Catppuccin Latte 有妥协。** 原版颜色在浅底上对比度不够：Solarized 的链接是灰色加下划线、成功色用蓝色；Latte 的链接和强调色同为紫色。
- **有事等你、卡片不在视野里时**，输入框上方浮一个"有 1 件事等你确认"的按钮，它下面的文字会淡出。
- 确认框还是浏览器自带的，没有另做。
