# 聊天为主的界面

版本 1 · 2026-11-21 · 给实现的人看的规格。

用户的原话：希望做成 ChatGPT 或者 Claude 应用那种聊天为主的，现在进来就是让放文件夹。

目标：打开就是对话，直接能说话。文件夹从"前提"变成"可选"：想让它处理某个文件夹里的东西时再连。参照 ChatGPT 和 Claude 应用的样子。

界面原则不变：简洁，有程序员工具的利落感，一看就会用；使用者是世界 500 强公司的管理者；文字直白、短。

## 1. 后端

### 1.1 默认空间

对话总得落在一个工作区里（工具只能读写工作区里的文件）。所以程序自己备一个默认的，用户不用管。

- `workspaces` 表加一列 `is_default INTEGER DEFAULT 0`（启动时迁移，幂等）。
- `Runtime` 增加 `ensure_default_workspace()`：没有 `is_default=1` 的工作区时建一个，名字"默认"。**只由 `agent/__main__.py` 在启动服务前调用**，`Runtime.__init__` 里不调，这样现有测试直接构造 `Runtime` 时不受影响。
- 它的文件夹：配置项 `default_folder` 有值就用它；否则数据目录是标准位置（`config` 里按平台算出的默认数据目录）时用 `<用户主目录>/CompanyAgent`；数据目录是用 `--home` 或环境变量另指的，用 `<数据目录>/files`。不存在就创建；建不了就退到 `<数据目录>/files`。
- `GET /api/state` 增加 `default_workspace_id`；每个工作区带上 `is_default`。
- 默认工作区不能删除（`DELETE` 回 400，说明原因）；可以改名、改指令。

### 1.2 上传文件

对话为主以后，得能把文件直接交给它。

- `POST /api/upload?workspace=<id>&name=<文件名>`，请求体就是文件的原始字节。上限是配置项 `upload_max_mb`（默认 50），超了回 413 和一句明白话；按 `Content-Length` 先判断，读的时候也要封顶。
- 存到工作区的 `上传/` 目录。文件名清洗：只留最后一段，去掉控制字符和路径分隔符，空名或清洗后只剩点的回 400；重名时在扩展名前加 `(2)`、`(3)`。落盘路径要过 `policy.resolve` 的路径守卫。先写临时文件再改名。
- 返回 `{"path": "上传/报表.xlsx", "name": "报表.xlsx", "size": 12345}`，写一行审计。
- `POST /api/sessions/<id>/message` 增加可选的 `files`（相对路径的列表，每个都要在该工作区里真实存在，否则 400）。存进 `user_message` 事件的 payload。
- 给模型看的时候，在这条用户发言的文字后面加一行：`（用户附上了文件：上传/a.xlsx、上传/b.pdf。先用 read_file、excel_inspect 等工具查看，再动手。）`。两个内核都要做（过渡内核在 `context.py` 投影事件的地方，新内核在 `lg/models.py` 的 `human_from_event`）。后台回顾的对话稿里，这条发言后面注明"（附文件 N 个）"。

### 1.3 选文件夹的系统窗口

现在加文件夹要手工粘贴路径，太别扭。运行时就在用户电脑上，可以直接弹系统自带的"选择文件夹"窗口。

- `POST /api/pick_folder`，没有参数。macOS 用 `osascript`（`choose folder`，返回 POSIX 路径，先把窗口带到前面）；Windows 用 PowerShell 的 `FolderBrowserDialog`；Linux 试 `zenity --file-selection --directory`。命令和参数都是固定的，不拼接任何用户输入。
- 最长等 120 秒。返回 `{"supported": true, "path": "/Users/…"}`；用户点了取消是 `{"supported": true, "path": null}`；这台机器弹不了或出错是 `{"supported": false}`，界面退回手工输入。
- 同一时间只弹一个，已有一个开着时回 409。
- 把实际调用包成一个可以在测试里替换的函数，测试不真的弹窗。

### 1.4 其他

- 导出文件名没有标题时用"对话记录.md"。
- `docs/实施说明.md` 加一节，`README.md` 的"启动"一节改成：启动后直接是对话，默认文件夹在哪，怎么连别的文件夹。
- 测试：默认空间（建一次、不重复建、三种位置的选择、不能删）、上传（正常、重名、名字清洗、超限、路径守卫、没口令 403）、带 `files` 的发言在两个内核里的投影（新内核的测试没装包时跳过）、选文件夹（替换掉真实调用：返回路径、取消、不支持、并发 409）。

## 2. 界面

### 2.1 进来就是新对话

- 打开直接到新对话页，默认空间已经选好。"先选一个工作文件夹"那一屏不再作为第一屏出现。
- 新对话页：居中一句问候（"今天想做什么？"），下面是输入框。占位符用聊天的口吻（如"问点什么，或者说一件要做的事"）。发送按钮是一个箭头图标，`aria-label` 是"发送"。
- 输入框左下一个"+"按钮，点开是菜单：**添加文件**、**添加图片**、**用一个文件夹工作…**。原来单独的"添加图片"按钮并进这个菜单。麦克风按钮和批准模式按钮保留。
- 在默认空间时，输入框周围不出现任何和文件夹有关的字样。连了某个文件夹时，输入框上方显示一个小标签"在「季度经营分析」文件夹里"，带一个 ×，点了回到默认空间。
- 模板区收成输入框下面的一行建议（最多 4 个，点了填进输入框），末尾"更多"展开原来的按岗位列表。

### 2.2 侧栏

从上到下：

1. "新对话"按钮。
2. 搜索框（"搜以前的对话"）。
3. "对话"列表：当前空间的对话，最近的在上。
4. "文件夹"小节：列出已连接的文件夹（不含默认空间）。点一个就切过去，上面的列表换成这个文件夹里的对话，再点一次或点"全部对话"回到默认空间。末尾一项"添加文件夹…"。没有连过文件夹时，这一节只显示"添加文件夹…"。
5. 底部导航：资料、记忆、定时、技能、设置。

原来顶部的"工作文件夹"切换器去掉，它的功能由"文件夹"小节接替（改名、移除这些操作放到每个文件夹的"⋯"菜单里）。

### 2.3 对话页

要像聊天，而不是像任务日志。

- 用户的话靠右，成气泡。助手的回答靠左，不带气泡，Markdown 渲染。
- **一轮里的工具步骤折成一行**：运行中显示"正在：读取 报表.xlsx…"（当前这一步），做完后变成"做了 5 步"，点开才看明细（明细就是现在的步骤条目）。出错的步骤折叠时也要在这一行上有提示（如"做了 5 步，其中 1 步出错"）。
- 批准卡片、提问卡片始终展开，直接显示在对话流里。
- 成品作为文件卡片跟在助手回答下面，点了预览或下载。
- 记忆、技能、"可以存成技能"这些提示条保持现在的样子。
- 顶部栏只留标题和状态。运行中，发送按钮变成"停止"按钮（等同于现在的"暂停"；停下后再发一句话或点"继续"接着做）。"取消对话里正在做的事"和"导出记录"放进标题旁的"⋯"菜单。
- 右侧"计划与成品"面板默认收起；有计划或成品时，顶部栏出现一个按钮可以打开。

### 2.4 把文件交给它

- 三个入口：菜单里的"添加文件"、把文件拖到窗口上、在输入框里粘贴文件。
- 图片文件走原来"给模型看图"的路径不变。其他文件调 `/api/upload`，传完在输入框上方显示成小卡片（名字、大小、×）。上传中有进行中的样子，失败给一句话，卡片可以移除后重传。
- 发送时带上 `files`。发出去的用户气泡里，附件显示成文件小卡片。
- 拖到窗口上时，整个窗口有一个明显的"松手添加"提示。

### 2.5 连接文件夹

"用一个文件夹工作…"和"添加文件夹…"都这样走：调 `/api/pick_folder` → 拿到路径 → 名字默认用文件夹名 → 直接建好并切过去，然后停在新对话页。返回 `supported: false` 时，弹出原来那个手工填名称和路径的表单（作为对话框，不再是整屏）。用户取消就什么都不做。

### 2.6 用词

界面上"任务"统一改成"对话"：新对话、搜以前的对话、对话列表、导出对话记录。"工作文件夹"改成"文件夹"。定时页里"到点新开一个任务"改成"到点新开一个对话"。

### 2.7 不变的

深色模式、窄窗口、键盘操作、语音输入、批准模式、记忆页、技能页、设置页、查找和跳转。全项目仍然只有 `renderMarkdown` 那一处给 `innerHTML` 赋值。旧版后端（没有 `default_workspace_id`、没有上传和选文件夹接口）时要能降级：没有默认空间就退回原来的"先选文件夹"流程；上传接口 404 时给一句明白话。

### 2.8 测试

`node --check ui/app.js && node tests/ui_test.mjs` 必须通过。新逻辑里能写成纯函数的都加测试：一轮步骤折叠后的那一行文字和状态（运行中、做完、有出错、被批准卡片打断）、附件列表的归一化和大小的显示、带 `files` 的用户事件归并、文件夹小节的排序和当前项、旧后端的降级判断。
