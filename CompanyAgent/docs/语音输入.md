# 语音输入

不想打字时，点输入框旁边的麦克风按钮直接说话，识别出的文字放进输入框，看一眼再发送。中文、英文都支持。

本文分三部分：给使用者的说明、给管理员的部署说明、上线前要做的实测。最后一节列出实现细节和还没验证过的地方。

---

## 一、使用者

### 怎么用

1. 在"新任务"的大输入框或者对话页底部的输入框旁边，点**麦克风按钮**（或者按 `Ctrl + Shift + M`，Mac 上是 `⌘ + Shift + M`；也可以在 `Ctrl/⌘ + K` 打开的查找框里输入"语音"）。
2. 第一次用时浏览器会问是否允许使用麦克风，点**允许**。
3. 按钮变成蓝色的方块，旁边显示已录时长和一条音量指示，这时开始说话。
4. 说完再点一次按钮（或再按一次快捷键）。旁边显示"正在识别…"，几秒后文字出现在输入框里**光标所在的位置**，原来写的字都还在。
5. 看一眼，需要就改一改，然后按回车发送。**识别结果不会自动发送。**

- 想放弃这次录音：按 `Esc`。识别中按 `Esc` 也会放弃，结果不会放进输入框。
- 一次最多录 3 分钟（管理员可以调整），到时间会自动结束并开始识别。长内容请分几段说。
- 录音和识别过程中不能发送，免得发出半句话。
- 录音只在内存里处理，识别完就丢掉，不保存成文件，也不记进任务记录和操作记录。

### 常见提示是什么意思

| 提示 | 意思和办法 |
|---|---|
| 没有麦克风权限 | 浏览器没被允许用麦克风。点地址栏旁边的麦克风或锁形图标，改成"允许"，再点一次麦克风按钮。Mac 上如果已经允许还不行，到"系统设置 → 隐私与安全性 → 麦克风"里打开浏览器的开关。 |
| 没有找到麦克风 | 电脑没有接麦克风，或者系统没认出来。接上耳机或麦克风再试。 |
| 麦克风被别的程序占用了 | 会议软件等正在独占麦克风。关掉后再试。 |
| 没有听到声音 | 录到的全是静音：麦克风静音了，或者系统选错了输入设备。 |
| 说话时间太短，没有识别 | 不到半秒，当作误点，什么都不做。 |
| 语音识别还没有设置好 / 还没有开启 | 管理员还没配置识别方式。提示里有"去设置"按钮，按下面"管理员"一节填写。 |
| 识别服务暂时连不上 | 公司的识别服务器没响应。稍后再试；一直不行请联系管理员。 |
| 识别太久没有结果 | 超过两分半没有结果，已放弃。稍后再试，或者说短一点。 |
| 没有识别出文字 | 识别服务没听出内容。靠近麦克风、说慢一点再试。 |
| 这个浏览器不能录音 | 请用最新版的 Chrome、Edge 或 Safari 打开。 |
| 识别好了，但你已经离开了原来的页面 | 识别期间换了页面，文字没放进去，可以点"复制文字"。 |

## 二、管理员

在 Agent 的"设置 → 语音识别"里选择识别方式，填好后点"测试"（用一段 1 秒的静音走一遍，结果为空是正常的，只看通不通），再点"保存"。也可以直接改数据目录里 `settings.json` 的 `asr` 一项：

```json
"asr": {
  "engine": "vllm",                       // off 关闭 · vllm 内网识别服务 · sherpa 本机识别
  "base_url": "http://10.0.0.1:8001/v1",  // 内网识别服务地址
  "model": "Qwen/Qwen3-ASR-1.7B",
  "api_key": "",
  "language": "",                         // 空 = 自动判断；zh 中文；en 英文
  "sherpa_model_dir": "",                 // 本机识别的模型目录
  "max_seconds": 180                      // 一次最长录多少秒（5 到 600）
}
```

两种方式怎么选：

| | 内网识别服务（推荐先上） | 本机识别 |
|---|---|---|
| 员工电脑 | 什么都不用装 | 要装 sherpa-onnx 和几百 MB 的模型文件 |
| 依赖 | GX10 要可达 | 断网也能用 |
| 模型 | Qwen3-ASR（0.6B 或 1.7B），52 种语言和方言 | SenseVoice（中、英、日、韩、粤） |
| 算力 | 占 GX10 的显存/内存 | 占员工电脑 CPU，几秒钟 |

### 1. 内网识别服务：在 GX10 上用 vLLM 起 Qwen3-ASR

> 来源：Qwen3-ASR 官方 README（https://github.com/QwenLM/Qwen3-ASR ，2026-11-20 查阅）。**以下命令未在本项目的环境里实测。**

官方给的两种启动方式：

```bash
# 方式一：直接用 vLLM（官方建议用较新的 vLLM，README 里给的是 nightly 版，并装上音频依赖 vllm[audio]）
vllm serve Qwen/Qwen3-ASR-1.7B

# 方式二：官方的 qwen-asr 包（pip install -U "qwen-asr[vllm]"），它是 vllm serve 的包装，可以带任何 vllm serve 参数
qwen-asr-serve Qwen/Qwen3-ASR-1.7B --gpu-memory-utilization 0.8 --host 0.0.0.0 --port 8000
```

在 GX10 上和大模型同机时，建议这样起（端口换成 8001，避免和大模型的 8000 冲突；只监听内网地址）：

```bash
vllm serve Qwen/Qwen3-ASR-1.7B --host 0.0.0.0 --port 8001 --gpu-memory-utilization 0.10
```

要注意的几件事：

- **vLLM 版本。** GX10 是 ARM 架构加 GB10 芯片，官方 README 里的 nightly 安装命令针对的是 x86 + CUDA 12.9 的轮子，不一定适用。建议沿用现在大模型那套 vLLM 的安装方式（同一个容器镜像或同一个环境），前提是那个版本已经支持 Qwen3-ASR；不支持就要单独起一个较新的 vLLM。
- **内存要留多少，需要实测。** `--gpu-memory-utilization` 是占整机可用显存的比例，GX10 的 128 GB 是 CPU 和 GPU 共用的。大模型那个服务已经按自己的比例占了一大块，两者加起来不能超过 1，还要给系统留余量。1.7B 的权重本身只有几 GB，但 vLLM 会把分到的比例全部预占作缓存。上面的 0.10（约 12 GB）只是起步值：先把大模型服务照常跑起来，再起识别服务，看两边都能启动、并发时都不报内存不足，再按需调整。内存紧时改用 `Qwen/Qwen3-ASR-0.6B`。
- **两台 GX10 都起一份**更稳，但 Agent 现在只认一个识别地址；要两台都用，前面加一个负载均衡入口，或者先只在一台上起。
- 起好后，在 GX10 上自测一下（把 `a.wav` 换成任意一段 16 kHz 的录音）：

  ```bash
  curl http://127.0.0.1:8001/v1/audio/transcriptions -F model=Qwen/Qwen3-ASR-1.7B -F file=@a.wav
  ```

Agent 怎么调用它（对照官方 README）：

1. 先发 `POST <地址>/audio/transcriptions`，multipart 表单，字段 `model` 和 `file`（`audio.wav`，`audio/wav`），语言设成中文或英文时多带一个 `language`（`zh`、`en`）。取回复里的 `text`。
2. 如果服务对这个路径回 404 或 405（没有转写接口），改发 `POST <地址>/chat/completions`，消息内容是 `[{"type": "audio_url", "audio_url": {"url": "data:audio/wav;base64,…"}}]`，取 `choices[0].message.content`。
3. Qwen3-ASR 的原始输出带语言标记，形如 `language Chinese<asr_text>识别出的文字`（官方用 `qwen_asr.parse_asr_output` 拆开）。Agent 只保留 `<asr_text>` 之后的文字；只有语言标记、没有文字时当作空结果。
4. 识别服务地址不走系统代理，每次请求超时 60 秒。有密钥时以 `Authorization: Bearer <密钥>` 发送。

### 2. 本机识别：sherpa-onnx + SenseVoice

> 来源：sherpa-onnx 的 SenseVoice Python 文档（https://k2-fsa.github.io/sherpa/onnx/sense-voice/python-api.html ）和官方示例 `python-api-examples/offline-sense-voice-ctc-decode-files.py`，2026-11-20 查阅。**这部分代码没有在本项目的环境里运行过**（开发环境没有安装 sherpa-onnx），上线前必须在一台员工电脑上实测。

每台要用本机识别的电脑：

1. 在 Agent 用的那个 Python 里安装 sherpa-onnx（建议同时装 numpy，转换样本更快；没有也能用）：

   ```bash
   python -m pip install sherpa-onnx numpy
   ```

   安装包要随 Agent 一起分发时，在能联网的机器上用 `pip download sherpa-onnx numpy` 下载对应平台的轮子，再离线安装。

2. 下载并解压 SenseVoice 模型（中、英、日、韩、粤）：

   ```bash
   curl -SL -O https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2
   tar xvf sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2
   ```

   解压出的目录里要有 `model.int8.onnx`（或 `model.onnx`）和 `tokens.txt`。Agent 优先用 `model.int8.onnx`（更小更快）。

3. 在"设置 → 语音识别"里选"本机识别"，"模型目录"填这个目录的完整路径，点"测试"。

Agent 怎么调用它（对照官方示例）：用 `sherpa_onnx.OfflineRecognizer.from_sense_voice(model=…, tokens=…, num_threads=2, use_itn=True, language=…)` 建识别器（建一次后缓存，同一时间只识别一段），然后 `create_stream()`、`accept_waveform(采样率, [-1, 1] 的浮点样本)`、`decode_stream(stream)`，取 `stream.result.text`。`language` 参数在官方示例里没有出现，老版本不认它时自动去掉再建。

## 三、上线前的实测

默认用哪种识别方式、用哪个模型，按实测定，不按公开资料定。

1. **录音样本。** 请几位实际使用者（最好有口音、语速不同的）各自在自己的电脑和麦克风上录，凑够 **30 条**：
   - 中文 10 条，英文 6 条，中英夹杂 8 条（例如"把 Q3 的 revenue 和 budget 对一下"），带人名、产品名、部门名、数字的 6 条；
   - 每条 3 到 20 秒，同时写下这句话的标准文字。
2. **两种引擎都测**（内网识别服务的 1.7B 和 0.6B 各测一遍更好，本机识别在一台普通配置的员工电脑上测）。
3. **算字准确率**：按字（中文按字、英文按词）比对识别结果和标准文字，准确率 = 1 − (替换 + 删除 + 插入) / 标准文字长度。分中文、英文、中英夹杂、专有名词四组分别统计，专有名词单独看错了哪些。
4. **量速度**：从点"停止"到文字出现在输入框。**短句（5 秒以内）不超过 3 秒**才算合格。同时记下 GX10 上大模型正在忙时的速度。
5. **定默认**：准确率高的为默认；差不多时选内网识别服务（员工电脑不用装东西）。本机识别留作 GX10 不可用时的备选。
6. 结果和样本留档，换模型或升级 vLLM 后用同一批样本再测一次。

## 四、实现说明

| 部分 | 文件 |
|---|---|
| 识别引擎 | `agent/voice.py` |
| 接口 | `agent/server.py`：`POST /api/transcribe?lang=`、`POST /api/settings/test_asr`；`GET /api/state` 多了 `asr_engine`、`asr_max_seconds`、`kernel` |
| 界面 | `ui/index.html`、`ui/app.js`（"语音输入"两节）、`ui/app.css` |
| 测试 | `tests/test_voice.py`、`tests/ui_test.mjs`（"语音输入"一节） |

**接口。** `POST /api/transcribe` 的请求体是原始 WAV 字节，`Content-Type: audio/wav`，和其他接口一样要令牌、Host、Origin 检查。返回 `{text, engine, seconds, audio_seconds}`（`seconds` 是识别用时）。出错返回 `{"error": 中文说明}`：没配置好 409，音频不合法、太长、太大 400，类型不是 audio/wav 415，识别服务不可用 502。`POST /api/settings/test_asr` 可以带 `{"asr": {...}}` 测试还没保存的设置（不保存；打码的密钥沿用原值），返回 `{ok, engine, detail}`。`GET /api/settings` 里 `asr.api_key` 打码，原样回传时保留原密钥。

**音频要求。** 16 位 PCM 的 WAV，单声道或双声道，8 kHz 到 192 kHz，不超过 20 MB，不超过 `max_seconds`。界面发的都是 16 kHz 单声道。

**界面录音。** `getUserMedia({audio: true})` 加 Web Audio：优先 AudioWorklet（处理器代码用 Blob 地址加载），加载失败、或开始后 1.5 秒还没收到任何数据，就换成 ScriptProcessor。AudioContext 在点击的同一时刻创建并 resume（Safari 要求）。结束后在前端把样本重采样到 16 kHz（降采样时按区间取平均，减少混叠）、编码成 16 位 WAV，上传。不用 MediaRecorder，不需要 ffmpeg。整段峰值低于约 −42 dBFS 时当作"没有听到声音"，不上传。

**音频不落盘。** 服务端只在内存里处理，不写文件，不进账本和审计；`tests/test_voice.py` 里有一个测试确认识别前后数据目录和工作区里没有新增文件、审计表没有新记录。

### 还没验证的地方

按出错可能性从高到低：

1. **真实的 Qwen3-ASR 服务没有接过。** 只对着自己写的假服务测过。特别是：vLLM 对这个模型是否提供 `/audio/transcriptions`、它的 `text` 里是否带 `language …<asr_text>` 前缀（两种情况都处理了）、`language` 字段是否被接受（不接受时可能报 400，届时把设置里的语言改回"自动判断"）。
2. **本机识别从没运行过。** `from_sense_voice` 的参数名、`language` 参数、`stream.result.text` 都按官方示例写，没有实跑。
3. **浏览器里的录音没有真机试过。** 开发环境没有浏览器和麦克风，录音、AudioWorklet、ScriptProcessor 的流程只在一个自己写的假 DOM 和假 Web Audio 里跑过。需要在 Windows 的 Edge / WebView2、Mac 的 Safari 和 Chrome 上各试一遍。
4. **`⌘ + Shift + M` 在 Mac 的 Chrome 上是浏览器自己的"切换用户"快捷键，**很可能被浏览器先拿走；Firefox 的 `Ctrl + Shift + M` 是响应式设计模式。按钮和命令面板不受影响。
5. GX10 上和大模型同机时的内存比例、并发下的识别速度。
