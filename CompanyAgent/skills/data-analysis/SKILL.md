# 表格数据分析（数字要可复核）

数字一律由代码算出来，不要心算，不要从样例行推断整体。

## 步骤

1. **看结构。** `excel_inspect`（xlsx）或 `read_file`（csv）：工作表、列名、行数、样例。弄清每列是什么、单位是什么。
2. **问清口径**（不清楚就 `ask_user`）：按什么维度（地区、产品、月份）、什么指标（收入、毛利、数量）、时间范围、含税还是不含税。
3. **列计划。** 三步以上先 `todo_write`。
4. **写代码计算。** `run_python`（当前目录是工作区根目录，结果用 `print` 输出）：
   - 读 Excel 用 `openpyxl`（`load_workbook(路径, read_only=True, data_only=True)`）或 `pandas`（如果装了）；读 CSV 用标准库 `csv`。
   - **先打印数据概况**：总行数、空值数、各列的最小值和最大值、维度列的取值个数。发现表头不在第一行、有合计行、有空行，先处理掉再算。
   - **再算指标**，并打印用来核对的数字：总计、分组合计之和是否等于总计。
   - 输出用 `print(json.dumps(结果, ensure_ascii=False))`，便于引用。金额保留两位小数。
5. **生成成品。** 要交付表格就用 `write_xlsx`（可以写公式，例如 `"=SUM(B2:B13)"`，用户能在 Excel 里复核）；要交付文字报告就用 `write_docx`。run_python 自己写出的文件不会登记成成品，所以最终交付物用 write_xlsx / write_docx 生成。
6. **汇报。** 结论先行，每个数字后面能对上代码输出。

## 汇报格式

- 一句话结论，带最关键的一两个数字。
- 三到五条发现，每条一个数字。
- 口径说明：用了哪个文件、哪张表、多少行，排除了什么（例如“排除了 3 行合计行和 12 行退货”）。
- 成品位置。

## 容易出错的地方

- **合计行被重复计算。** 表格最后常有“合计”行，读数据时先排除。
- **文本型数字。** “1,200.00”“¥300”是文本，要先清洗再转成数字；转换失败的行数要打印出来。
- **日期格式混杂。** 统一转成日期再分组；转换失败的要列出来。
- **同比环比的基期为 0 或缺失**时不要算出无穷大，写“基期无数据”。
- **样本太少**时不要下趋势结论。
- 代码报错时读错误信息再改；同一个错误连续两次就停下来告诉用户。
